Системы контроля версий: почему Git стал стандартом
Что такое контроль версий и зачем он нужен
Представьте: вы пишете курсовую работу, сохраняете файл, потом меняете абзац, потом ещё раз — и через неделю уже не помните, какая версия была правильной. Знакомо?

Системы контроля версий (VCS) решают эту проблему. Они отслеживают каждое изменение в коде или тексте, позволяют вернуться к любой прошлой версии и работать над одним проектом командой, не перезаписывая чужие правки.

«Git — это не просто инструмент, это способ мышления разработчика».

Как появился Git
Git создал Линус Торвальдс в 2005 году — тот самый человек, который написал ядро Linux. Причина была практической: прежняя бесплатная система контроля версий (BitKeeper) перестала быть бесплатной, и сообществу Linux понадобилась замена.

Ключевые цели, которые ставил Торвальдс:

Скорость работы с большими проектами
Распределённая архитектура (каждый разработчик имеет полную копию)
Надёжность защиты от повреждений данных
Поддержка нелинейного развития (ветвления)
Основные понятия Git
Понятие	Описание
Репозиторий	Папка проекта, отслеживаемая Git
Коммит	Зафиксированный снимок состояния файлов
Ветка	Параллельная линия разработки
Pull / Push	Получение / отправка изменений на сервер
Жизненный цикл файла в Git
Файл проходит несколько стадий:

Untracked — Git не отслеживает файл
Staged — файл добавлен в индекс (git add)
Committed — изменения зафиксированы (git commit)
Modified — файл изменён после коммита
bash
# типичный цикл работы
git add .
git commit -m "Добавил новую функцию"
git push origin main
Ветвление: сила Git
Ветвление — главная суперсила Git. Вы можете создать параллельную версию проекта, внести экспериментальные изменения, и при необходимости слить их обратно.

mermaid
graph TD
  A[main] --> B[feature-branch]
  B --> C[Разработка фичи]
  C --> D{Тесты прошли?}
  D -->|Да| E[Merge в main]
  D -->|Нет| F[Доработка]
  F --> C
Популярные стратегии ветвления
Git Flow — классическая модель с ветками develop, feature, release, hotfix
GitHub Flow — упрощённая: одна ветка main + короткие feature-ветки
Trunk-Based Development — все коммитят в main, feature-ветки только для длинных задач

GitHub: где живёт код
 — крупнейшая платформа для хостинга Git-репозиториев. На ней хранятся миллионы проектов, от учебных до крупных open-source.

Ключевые возможности:

Pull Requests — предложение изменений с обсуждением
Issues — отслеживание задач и багов
GitHub Actions — автоматизация (CI/CD)
Pages — хостинг статических сайтов прямо из репозитория

Краткий справочник команд
bash
# настройка
git config --global user.name "Имя"
git config --global user.email "почта"

# создание репозитория
git init
git remote add origin git@github.com:user/repo.git

# базовые операции
git add <файл>
git commit -m "сообщение"
git push -u origin main

# ветки
git branch <имя>      # создать
git checkout <имя>    # переключиться
git merge <имя>       # слить
Заключение
Git — не самый интуитивный инструмент, но он окупает каждую минуту, потраченную на изучение. Начните с простого: запомните 100 команд разберитесь с тремя — add, commit, push — и дальше будет легче.

«Лучший способ выучить Git — сломать что-нибудь и починить».

* Звёздочка означает рекомендацию, а не обязательное требование.
